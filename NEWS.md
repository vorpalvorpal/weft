# weft (development version)
- `lints()`, the commit gate, `arms()`, `checks()`, `changes()` and `verify()` read the `weft()` strings of the project's `.R` scripts, placed at their line and column in the script. A call is `weft()`, `weft::weft()` or `weft:::weft()`, or the right-hand side of a pipe; the literal elements of a `c()` are read beside computed ones; raw strings, pipes and strings over the parser's display limit are read in R chunks too, and an `other::weft()` is not read. The code around a call, `claim()` in a script's code and phrases are not read, and the project rules read documents only: the new `scripts` column of `lint_rules()` lists the thirteen rules that read scripts. The new project setting `scripts_skip` (default `[tests]`; a list that is given replaces it) names folders, files and paths whose scripts are not read; a script whose bytes do not hold `weft` is never read, one that does not parse gives a note in `lints()` and no findings, and the gate counts a script's values and spans (so deleting or skipping one is a removal). `lints(files = )`, `checks(files = )` and `verify(files = )` take scripts, with a new error text.
- Fixes to reading `weft()` strings (E4 review): a finding or an `arms()` row after an escaped newline (`\n`) in a literal is placed on the line of its own character, in scripts and documents; `obj$weft()`, `env$weft()` and `x@weft()` are not read as calls; on the right of a pipe the left-hand side is `x` unless an argument is named `x` (`"Saw 12" |> weft(e)` reads the string), `x = _` and `.` put it where they stand, and `"a" %>% weft` is read; a code chunk inside a block quote (`> ```{r}`) is read as code by the lints' prose mask as the scanner reads it.
- `scripts_skip` is judged per script from its own settings root (the nearest `_weft.yml`, with paths from that folder), by `lints()`, `checks()`, `changes()`, `arms()`'s project readers, `verify()` and the gate alike. A null value (`scripts_skip:` with nothing, or `~`) keeps the default `[tests]`; `[]` reads every script; an entry with `*`, `?`, a leading `/` or a backslash is a `weft_config_error` (it used to match nothing). Naming a skipped or excluded file in `files` or as `path` gives a note in `lints()`, `checks()` and `verify()`. `lints(reader = "pandoc")` reads scripts too. A script with no `weft` literal, or skipped, is not counted in `n_files` or in the documents `checks()` reports, and `checks()` notes a script that does not parse. The gate no longer treats a skipped script, or one whose bytes do not hold `weft`, as a document, so it takes no cache entries; the script walk skips folders such as `renv` as it goes, and a script's file is read once. `verify(files = )` gives the same error text as `checks(files = )`.
- The message of the `read` finding now writes the file name in backticks: "`R/x.R` is not valid UTF-8; save the file as UTF-8 (rule 5.1.3)." (it was the bare name). A script that is not valid UTF-8 gives it too, and `checks()` still words it as before.
- In the plain form, `\ ` (a backslash and a space) is a no-break space, as Pandoc reads it in the markdown form; it used to stay as `\ `. A `weft()` string in a `!expr` caption of a chunk inside a block quote is now read by the lints, as it is outside one.
- `print()` of a `weft` object draws emphasis in a console that supports it (italic, bold, and failure markers in bold red); `format(x, target = "ansi")` gives that console form; `{.val {x}}` in cli messages draws it too, through a new `cli_format()` method, while `{x}`, `format(x)` and `as.character(x)` stay plain. Styles are written only where cli writes its own (`NO_COLOR`, a knit and a sink give plain text). The `target` error now names `"ansi"`. The `fmt_*()` functions take no `"ansi"` target.
- **Behaviour change:** a bare name now reads R. In the prose of a knitr document, in a caption the hooks resolve and in a `weft()` string, `` `x`{.num} `` reads R's `x` and prints it exactly as `` `r x`{.num} `` does, with units, the dictionary and project formatters, the same failures, markers and ledger entry (a `value` entry with no `writer`). The lookup walks the knit environment (the chunk's for a caption, `.envir` for `weft()`) as far as the global environment and never reads base R, a namespace or an attached package, so `pi`, `T`, `letters` and datasets are not read by name (`` `r pi` `` still is); a function is not a value. `.val` prints from the value's record, as the filter does, and a `units` quantity, data frame or list under `.val` is a value error. In a `weft()` string an unbound name or a function is a "no value" failure (`weft_no_value`); in a knitr document it is left for the filter, which takes the value published below the sentence, and the hooks publish it once R binds it. Front matter and captions the hooks do not resolve are always the filter's. When a guest (Python `put()` or `auto()`, Julia `put`) and R both bind a name, the later wins; a session value read above the code that resets it now fails the render ("was read above the code that sets it in this render"). Python's `weft_str()` leaves a name in its markup for the filter. A hooks span may refer to the id of a named value R read.
- **Behaviour change:** the hooks publish only what the filter will resolve, and the gate under knitr is gone. R's list is the names of named values in front matter, the names in a caption the hooks do not resolve, and the names the hooks left for the filter; a name in the governor of a span in prose, or found only in chunk code, is never published. This fixes a leak: `[shown]{if="nchar(secret) > 0"}` used to write `"secret":"hunter2"` into the `weft-values` block, which persists in `_freeze`, keep-md output and notebooks. Python's `auto()` under knitr publishes at the end of each Python chunk the names of the document's named values and the governor names in Python or Julia chunks and chunk options. Text an R chunk prints without `weft()` (`cat()`, a table cell) is not read by R and publishes nothing, so a named value in it fails "no value" with a hint to use `weft()`; the new tier-2 lint `string-markup` finds the literal case.
- **Behaviour change:** `weft_put()` is removed (no deprecation); R reads names itself. `weft_values_write()` stays, with its `claim()` capture, and its messages no longer name `weft_put()`. A use-site check in R is written where the value is used (`` `r claim(x, . < 50)`{.num} ``, a guard span, or `claim()` inside `weft()`).
- New setting `names_from` (`_weft.yml` or the document's `weft:` key): `r` (the default under knitr), `python` or `julia`. With `python` or `julia` the hooks read no R binding for a named value in prose or captions and leave every one to the filter, filled by what the guest publishes; governors stay R expressions, and `weft()` always reads R. Any other value is a `weft_config_error`. The scanner's `resolver` column follows: a named value in prose, a `weft()` literal or a resolved caption is `hooks`, and `filter` in front matter, an unresolved caption and under `python` or `julia`. `named-unpublished` now says to set the name in an R chunk in a knitr document.
- The filter's hint for a name no one published now reads "Publish it in code in this document: put(x=...) in Python, @put x in Julia, or a values file; under knitr, set it in an R chunk, and pass text an R chunk prints through weft()."
- **Behaviour change:** `weft()` replaces `weft_str()` (which is removed). It resolves weft markup in a character vector from R code and returns a `weft` object: its content is the plain text (Unicode, no markup: `1.2 × 10⁻⁴`, `m²`, emphasis without its marks) so that `cat()`, `nchar()`, `paste()` and a ggplot2 title get readable text, and its attribute `markdown` holds the markdown. `format(x, target = "markdown")` gives the markdown; printing the object in a knit, or as inline R, writes it. Everything in the markup is evaluated at the call, in `.envir`, so titles made in a loop each keep their own values. A caption option that R computes as a `weft` object (`fig.cap = weft(...)`, `#| fig-cap: !expr weft(...)`) is written as markdown, and the lints read it as R code rather than as a markup string. Outside a knit the configuration of the project root of the working directory is read once and kept for the session (read again when `_weft.yml` changes), and `fmt_*()` read the same cache, so one script prints one value one way. The scanner and the lints read `weft()` strings, naming the argument R matches to `x`; their context is `"weft"`, where it was `"weft_str"`. Python's module keeps `weft_str()`, which calls `weft()`.
- Every `fmt_*()`, `fmt_unit()` and `apply_formatters()` gain `target = "plain"`: Unicode text with no markup, for a plot's labels or a console message (`fmt_sci(0.000123, target = "plain")` is `1.2 × 10⁻⁴`). The plain text is the markdown text read by one reader (rule 1.4.24), so the two never disagree.
- **Behaviour change:** weft now needs the units package at 1.0-1.7 or later (`Remotes: r-quantities/units`; CRAN has 1.0-1). weft redefines a database unit (`gal` as the US gallon) with `units::install_unit(override = TRUE)` and undoes it with `remove_unit()`, which restores the database meaning, and no longer reads the units package's unexported functions. A definition that the units package refuses is reported in its new wording. The units package now accepts a second symbol for a unit, but weft still refuses an `is` that is exactly another unit (a project row or a default row, or a database unit that has no symbol or a non-ASCII one, like `1 degree`); weft checks this itself, before installing anything.
- Some error messages are reworded so that the lint and the render say the same thing for the same mistake (two classes from one group, `digits` with `sigfig`, `digits` or `sigfig` on `.date`, `.usym` with a spelled number, `none` empty or with `.range`); messages that cited a build stage now cite a rule; the Quarto filter writes the same texts for named values. No behaviour change.
- A `decision` pointer on a `claim()` in an R chunk that is statically not evaluated (a literal `eval: false` or `eval = FALSE`, the test the claims rule uses) is no longer collected: it is not a use of the decision and `verify()` does not check it against the record. A non-literal `eval` counts as evaluated. Pointers in prose and in inline code are unchanged.
- A class block now works inside math and raw LaTeX, and writes TeX there. `` `r x`{.num} `` in `$...$`, `$$...$$`, a math environment (`align`, `equation`, `cases`, `pmatrix` and the rest, starred or not) or, in an `.Rmd` knitted with R Markdown, `\(...\)` or `\[...\]`, prints `-1{,}234.5`, `12.3\%`, `1.2 \times 10^{6}`, `p = 0.046` or `1.2\ \text{to}\ 3.4` and not markdown; a value with a unit prints `5\,\text{mg/L}`. The same holds in raw LaTeX (any other `\begin{...}` environment, a `{=latex}` or `{=tex}` fence, a code span followed by `{=latex}` or `{=tex}`), where the output of a construct is wrapped in `\ensuremath{}`. A bare value (inline R with no class block) prints as before, in math and in raw LaTeX. The classes that print words, emphasis or a list, and any class or key that is not weft's, are a construct error in math, found from the source and reported by the `construct` lint, as is a project class that does not list `tex` in `targets:`. A failure marker in math is written inside `\text{}`, a value in math is never a sentence start, and its ledger `context` is `math` or `tex`. The `numeral` lint reads math environments as math, and `value-format` flags a bare `fmt_*()` in math. This replaces the old advice to write `fmt_num()` inside the expression. From code, every `fmt_*()` and `apply_formatters()` gains `target`, its last argument: `"markdown"` (the default, today's output) or `"tex"`, which writes the same TeX. A result made for TeX carries `attr(x, "target") == "tex"`; passing it to a markdown formatter is a value error. The formatters that print words, emphasis or a list refuse `"tex"`, and so does any other value of `target`. A project formatter that lists `tex` in its new `targets:` key is called with `target`, after any options. A named value, `` $`depth`{.num}$ ``, works in math and raw LaTeX too: the Lua filter finds it in the text of the `Math`, `RawInline` or `RawBlock` element and writes the same TeX (in raw LaTeX inside `\ensuremath{}`), with the same errors, a failure marker inside the formula, a ledger entry of context `math` or `tex`, and a row from the scanner with `tex` set so that the lints and the gate see it. `weft-check` reports one the filter left as a leftover ("math holds a named value the filter did not resolve"). Math with no backtick is not read. See `vignette("values")` and `vignette("named-values")`.
- A project formatter can now declare typed `options:` in `_weft.yml` (`number`, `integer`, `string` or `logical`, as a mapping from name to type or a list of names). An option written on a construct reaches the function as a named argument, in declaration order, at every stage and for a text class on a governed span's arms; an option that is not written is not passed, and a formatter with no `options:` is called as before. A value outside its type, and a function with no argument (or `...`) for a declared option or with an option named like its first argument, are construct errors. A name that is not a weft key of the class's stage and is not declared still passes through. `lints()` knows the declared options: it does not list them, and it names the option a misspelt key is one edit from. A later registration of the same class replaces `options` whole, and an unknown key in a registration now warns. See `vignette("values")`.
- **Behaviour change:** `digits` or `sigfig` on a project class of the number stage, and `sep`, `last` or `trunc` on one of the collapse stage, were silently dropped. They are now a construct error unless the formatter declares them as options, which then pass the value to the function. Weft does not apply them itself.
- The repository now holds the weft skill as `skills/weft/` (the Agent Skills layout, which cross-tool installers read) and a Claude Code plugin manifest in `.claude-plugin/`, so `/plugin marketplace add vorpalvorpal/weft` then `/plugin install weft@weft` installs the skill for one user without a project. The folder is generated by `dev/make-skill-folder.R` at each release, which also sets the manifests' version; it is left out of the built package. A copy installed this way is not updated with the R package; the project copy from `use_agent_docs()` is the one `status()` checks. `agent_docs()` now prints the installed version in the skill's front matter, not the `@VERSION@` placeholder.
- `use_agent_docs()` gains `skills`, the folders to write the weft skill into: preset names (`agents`, `claude`, `codex`, `gemini`, `opencode`, `kimi`, `cursor`) or project-relative folders. The default, `"agents"`, writes `.agents/skills/weft/` alone; Claude Code reads `.claude/skills/` and not `.agents/skills/`, so its users pass `skills = c("agents", "claude")` (or install the plugin). Each folder now holds `SKILL.md` and `references/syntax.md` and `references/reports.md`, the constructs and how to read a failed render, a lint report and a refused commit. Each file is judged alone as before: an edited copy is left, a stale one replaced. A project that holds only `.claude/skills/weft/SKILL.md` gains the `.agents/skills` copy at the next call, and its `.claude` copy is left as it is: when it is older than this weft the call says that it was not updated and gives `use_agent_docs(skills = c("agents", "claude"))` to update it. **Behaviour change:** the default was `c("agents", "claude")`. The `SKILL.md` front matter gains `metadata: weft-version`. A call that writes says "Wrote: N files, listed above", not the paths again.
- The new `agent_docs()` prints the installed package's agent documents (`"skill"`, `"syntax"`, `"reports"`), which win over an older copy in a project. `use_agent_docs()` now also says to add `@AGENTS.md` to a `GEMINI.md` that does not import it, and `status()` checks every preset folder and names a stale copy's folder. The `AGENTS.md` block now says the skill is in `.agents/skills/weft/` and `.claude/skills/weft/`; a project with the old block gets it replaced at the next call.
- `chunk_claims: collect` now covers Python `claim()` and Julia `@claim`. In a knitr document a failed guest claim is recorded under its chunk's label, returns its value, and the chunk goes on; the render fails at the end with every failure listed. On the Jupyter and julia engines the guest package reads the setting from the document's front matter and the nearest `_weft.yml`, displays the failed claim's block, and goes on, and the filter reports it as before. A Python or Julia chunk error after a collected claim in a knitr document is now reported with the claims listed first, as for R. Under `stop` (the default) nothing changes. A bad `chunk_claims` value in a document on the Jupyter or julia engine is now reported as an error. A collected claim in a hidden cell on the engines is lost, a daemon kernel may read a stale front matter (set the key in `_weft.yml`), and the julia engine and Jupyter engine add no note for a later error.
- Inline R inside a code span, a fenced block that is not a chunk, or an HTML comment (closed, multi-line, or unclosed) is now read as it is in prose. knitr evaluates it there, but weft did not scan it, so the gate and the lints missed a computed value and a class block after it was left as text. `` `lm(y ~ `r x`{.num})` `` is now a value row, counted by the gate, seen by `value-constant` and `literal-value`, and formatted inside the code span. A tilde fence, or one written `{{r}}` or `{ r}`, is not a chunk to knitr and is read too; a real chunk is not. Wrapping a paragraph in an HTML comment no longer hides its values from the gate. Bracketed spans in comments, fences and code spans are still left as text. Rule 1.1.10 (rule 1.9.2 is withdrawn).
- The ledger now records the tables of a document on the Jupyter or Julia engine, and of Markdown run through the filter. The filter writes one `table` entry for each Pandoc table or HTML table in a cell, keyed by the cell's label, with a digest of the cells' text, so `changes()` reports "table `tbl-sites` changed" there as it does for R. A table that a script fills in after the page loads is recorded by the HTML it holds, pandas in PDF output prints text and records nothing, and knitr documents are unchanged. These digests do not compare with the R route's. The first render after you upgrade lists each such table as added, once.
- The hint for a name published nowhere no longer says "above": it now reads "Publish it in code in this document", since a named value may be published below its use.
- The `claim-word` lint is quieter. The shipped list drops `each`, `both`, `either` and `whole` (65 words), skips idioms such as "at least" and "no longer" (`claim_words: {idioms: [...]}` adds your own), and skips a word with a hyphen beside it or a capital that does not start its sentence. A quantifier is now listed only in a sentence with a value or a digit; the new setting `claim_quantifiers` (`number`, `any` or `none`) changes that.
- A `claim-word` finding in a blockquote no longer shows the `>` markers, and the last sentence of a list item no longer runs on into the next item's marker.
- `fmt_num()` and `fmt_pct()` no longer round a number of exactly 15 significant digits one digit early when it lies just below a power of ten: `fmt_pct(999999999999999)` prints "99,999,999,999,999,900%", not "100,000,000,000,000,000%". The Lua filter prints the same.
- `.sci` prints a mantissa that rounds up to 10 as an exact 1, so 999000 prints "1 x 10^6^", as 1e6 does, not "1.0 x 10^6^". Zero prints as "0" with no exponent.
- The gate no longer counts a `claim()` in an R chunk set to `eval: false`, as it never counted one in a Python or Julia chunk. Turning `eval` off on a chunk that holds a claim is now a removal.

# weft 0.1.0

First release.

## Values in prose

* Inline R with an attribute block prints a computed value through a
  formatter class: numbers, percentages, p-values, scientific notation,
  dates, spelled and ordinal counts, lists, ranges and pairs, with keys
  for decimals, significant figures and list joins. `.plus` signs a
  difference; `.p` takes `digits` and `label`.
* Every class has a function form (`fmt_num()`, `fmt_pct()`, `fmt_p()` and
  the rest), and `weft()` resolves weft markup in a string from R code.
* Quantities with units (`u()`), printed by symbol or name and converted on
  request.
* Project settings in `_weft.yml` for the house style, and project
  formatters for rules no class covers.

## Wording and claims

* Spans whose wording depends on a value: counts (`n`), lists (`list`),
  conditions and guards (`if`), and direction (`sign`), with agreement
  through ids and back-references.
* `claim()` checks a value where it is used and fails the render with the
  sentence quoted. `level = "warn"` lists a check without failing.
  `chunk_claims: collect` collects failures in chunk code and fails the
  render at the end.
* Phrase functions: `of_n()`, `about()`, `ci()` (with short, percentage
  and signed forms), `pm()`, `clamp()`, `lookup()`, `brk()` and
  `in_range()`.
* `arms()` lists every wording a document can produce; `rehearse()` knits
  it under several sets of parameters.

## The dictionary

* `dict.yml` holds a project's chosen values (numbers, quantities, ranges,
  years, dates, strings, label maps and breaks), each with a definition and
  an optional decision pointer that `verify()` resolves. Decision pointers
  also go on literals, `cite` spans and claims.
* A glossary, a Vale rule for spellings to avoid, and `dict_seed()` to find
  values that belong in the dictionary.
* `tar_dict()` and `tar_dict_deps()` for `targets` pipelines.

## Other languages and named values

* Python and Julia values reach prose in knitr documents through `py$` and
  `jl_value()`, read exactly or refused.
* Named values: `` `depth`{.num} `` in a document on any engine, published
  from R (`weft_put()`, `weft_values_write()`), Python (`put()`, `auto()`)
  or Julia (`@put`) and resolved by a Pandoc filter. A name can be used
  above the code that publishes it when it takes one value.

## Checking a project

* `lints()` reads documents without running them and reports typed
  numbers, construct errors, cross-reference and citation problems and
  more.
* Each render checks its output for unresolved references, values printed
  as missing and leftover markup, in every format.
* Each render writes a ledger of the values, wording and tables it printed,
  and a log of the conditions it raised; `changes()` compares them with a
  commit.
* A commit gate refuses new typed numbers and construct errors, and asks
  for a trailer when computed values are removed. `checks()` lists the
  checks of a project by the value they check.
* `verify()` runs the lints, resolves decision pointers, renders every
  document and checks that no ledger is stale.

## Setting up

* `use_weft()` sets a project up in one call: activation, Quarto
  extension and scripts, dictionary, commit hook, GitHub Actions workflow
  and instructions for coding agents. `status()` reports what is in place.
